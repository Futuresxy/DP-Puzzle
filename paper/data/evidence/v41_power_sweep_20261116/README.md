# 严格功耗预算下的 V4.1 核心负载分析

> 状态更新（2026-11-16）：用户已撤回本批次的论文探索内容，当前研究范围为 β=1–2.1。本目录保留历史证据，不作为当前论文结论；对应图已退出正文，脚本已退出默认复现入口。以下方法、结果与 `make power-sweep` 命令描述均为历史执行记录，该 Makefile 目标现已移除。

本批次沿用冻结 DP 测量和六种精度场景，新增解析扫描，没有新增 EDA 或模型推理测量。执行入口：`MPLCONFIGDIR=/tmp/dp-paper-mpl make power-sweep`。输入和输出 SHA-256 见 `manifest.json`。

## 比较口径

- α=0.2/0.3/0.4；β 从 0.50 至 1.50、步长 0.01，另保留 β=2.1。
- 九种设计、六场景、11 个对数间隔上下文；A/B、A–E、A–F 另外评价固定芯片覆盖。主扫描为均衡权重、充分利用。
- 一个候选在每个预算下有一个固定整数 SM 数，必须同时满足三个已测模式的全核运行功耗约束。β<1 时基准配置也缩小，速度比使用同预算基准。
- 连续部署同时去除面积和功耗取整，仅用来区分整数效应与资源机制，不作为可制造芯片。
- α=0.3、β=0.75/1/1.5 追加三类请求分布、五组专家利用率敏感性；非理想利用率的能耗留空。
- 所有功耗预算均为 DP 池口径；外围面积按原模型固定。预算放宽不会令任何固定候选的绝对时间变差，脚本逐点检查此性质。

## 1. 最大 QE 配比可以在全部精度上被较小设计覆盖

α=0.3、β=1 时，`1:4:8` 配置 20 核，`1:8:16` 配置 10 核。二者的整芯片 Q/E 峰值同为 655.36/1310.72 TFLOP/s；H 峰值分别为 163.84/81.92 TFLOP/s。因而任何具有 H 工作量的组合，后者都更慢；纯 Q/E 工作量时两者相等。`1:6:12` 也被 `1:4:8` 的三项峰值覆盖。这里是算力向量的支配关系，不是包含能耗的 Pareto 支配。

这一结果和整数配置有关：连续松弛下，D 场景仍可选择 `1:8:16`。不把 β=1 的支配关系推广为所有预算下的硬件劣势。

证据：`deployments.csv`、`capacity_dominance.csv`。

## 2. 94%–96% 的 FP4 FLOP 仍不足以选择最大的 E 扩展

β=1 时，F 场景的 FP4 占比在 1K/1M 时分别为 94.17%/95.62%，全部 11 点范围为 94.03%–95.62%，但全部 11 个上下文仍由 `1:2:12` 取得最低时间。`1:2:16` 中剩余 FP8 仅占 5.79%/4.35% 的 FLOP，却占 32.85%/26.59% 的计算时间。

β=1 的 `1:2:12`/`1:2:16` 分别部署 24/19 核。后者 E 峰值仅提升 5.56%，H/Q 峰值下降 20.83%。若残余工作全部为 Q，两者等时间边界为 E 占比 96.77%；若残余工作全部为 H，边界上升至 98.36%。两项阈值只描述这两个设计之间的比较，不是九设计全局最优边界。

因此，FLOP 占比小只能作为减少迁移开关的依据，不能作为删除工作量的依据。应检查 `x_p/C_p` 的服务时间占比。

证据：`service_breakdown.csv`、`pairwise_thresholds.csv`。

## 3. 强功耗限制下，β 主要改变规模而非连续模型的排序

记 `pmax_j=max_p(p_jp)`。所有候选均受功耗限制且忽略取整时：

```text
n_j = beta * P_ref / (D * pmax_j)
C_jp = 2*f*beta*P_ref*K_jp / pmax_j
T_j = F/(2*f*beta*P_ref) * pmax_j * sum_p(x_p/K_jp)
```

固定工作量下所有候选时间都乘共同的 `1/beta`，相对排序和 regret 不随 β 变化，面积参数 α 也不进入该表达式。α=0.3 时连续模型的首个面积饱和阈值为 0.97329，来自 `1:2:6`；整数模型全面积部署阈值为 0.96525。

在 β=0.50–0.96 的 47 个采样点，C/E 的整数和连续选择均为 `1:2:8`；A–F 均为 `1:2:8`。F 的连续选择始终为 `1:2:12`，整数选择则有 36 点 `1:2:12`、7 点 `1:2:16`、4 点 `1:2:8`。这些局部切换不应写成新的精度规律。

证据：`limits.csv`、`selections.csv`；测试检查低预算下不同 α 的连续容量一致及其随 β 线性缩放。

## 4. 最坏模式的功耗会约束其他模式的可部署数量

共享多模式设计要求所有模式均可全开，因此功耗受限时的吞吐指标为 `K_jp/pmax_j`，而单位工作能耗对应 `p_jp/K_jp`，两者分母不同。`1:8:16` 的最大模式功耗是 Q 的 52.85 mW，E 功耗为 38.91 mW；其连续功耗受限部署在 E 模式仅消耗约 73.61% 的预算。这解释了为 Q 扩展的资源为什么会限制 E 密集负载下的部署密度。

该机制来自当前“三种模式均可全开”的配置合同；本批次没有改成工作量平均功耗部署，也没有加入 DVFS 或运行时关核。

证据：`limits.csv`。

## 5. 放宽功耗预算可加剧固定芯片的相对覆盖损失

α=0.3 下，A–F 的最小最坏损失为：

| β | 固定配比 | 最坏损失 | 该配比的均衡平均计算时间（s） |
|---|---|---:|---:|
| 0.50 | 1:2:8 | 12.49% | 8.9066 |
| 0.75 | 1:2:8 | 12.49% | 5.9377 |
| 1.00 | 1:2:8 | 12.49% | 4.4533 |
| 1.25 | 1:2:8 | 35.14% | 4.4533 |
| 1.50 | 1:6:12 | 49.29% | 4.1889 |
| 2.10 | 1:8:16 | 16.70% | 3.2390 |

小设计先达到面积上限，增加功耗预算后容量不再增加；大设计继续增配并拉低某些精度场景的单点最优时间，从而扩大固定芯片与单点理想选择的相对差距。连续模型中同样存在这一趋势：β=1/1.5 的 A–F regret 为 10.87%/46.84%。

这不意味着更低预算的芯片更快，或应该主动收紧预算。绝对时间与相对覆盖损失的参照不同，必须同时报告。该表也不把 F 预设为必须支持的近期质量可行场景。

证据：`checkpoints.csv`、`selections.csv`；图 `figures/v41_strict_power.pdf` 的面板(c)对照整数与连续部署。

## 数据与稿件

- `checkpoints.csv`：代表预算下所有候选的跨上下文指标、能耗和 Pareto。
- `selections.csv`：完整预算扫描的 minimax 选择；0.01 的采样切换只能定位区间，不能视作精确阈值。
- `sensitivity.csv`：利用率及请求分布敏感性，保留所有候选。
- `deployments.csv`：整数部署、模式峰值和连续松弛容量。
- `service_breakdown.csv`：β=1 时各上下文/场景/候选的 FLOP 与服务时间分解。
- `review.json`：执行检查、数值核对和图稿检查记录。

本批次把论文主张收敛到预算下的有效精度容量、残余高精度工作和跨场景覆盖，而不把单一 β 下最大的低精度配比作为结论。作者仍需确定迁移场景的质量可行范围。
